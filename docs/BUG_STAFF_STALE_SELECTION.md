# Bug 草稿：Staff 快速切換報修時，較慢的回應把畫面與儲存目標切回前一筆

可直接貼到 Jira（類型選 Bug）。「發現者」、「相關 Story key」、日期請填實際資料。

| 欄位 | 內容 |
| --- | --- |
| 摘要 | Staff 先點 #1 再點 #2，較慢回來的 #1 回應把畫面和儲存目標切回 #1 |
| 相關 Story | S4 View Reports as Staff、S5 Update Report Status（key 待填） |
| 嚴重度 | Major：狀態會寫到錯誤的報修，學生看到錯誤的進度，但有辦法避開（等畫面載完再操作） |
| 發現者／日期 | （填實際發現的組員與日期） |
| 環境 | 本機 `python app.py`，Chrome |

**重現步驟**

1. 用 `staff` 登入 Staff 管理頁。
2. 在左邊列表點 #1，在 #1 的詳情還沒載完前，馬上點 #2。
3. 等 #1 的回應比 #2 晚回來（網路慢時容易發生；可用 `tests/e2e_staff_race.cjs` 穩定重現）。
4. 狀態選「處理中 In Progress」，按「儲存狀態」。

**預期結果**　畫面維持顯示最後點選的 #2，更新寫進 #2，#1 不變。

**實際結果**　畫面被切回 #1、列表反白也回到 #1；按下儲存後更新寫進 #1，最後點選的 #2 維持原狀。

**證據**　修正前執行重現腳本的輸出：

```text
點 #2 後 0.4 秒畫面：報修 #2 → #1 回應抵達後畫面：報修 #1，反白 #1
儲存訊息：已儲存。報修 #1 目前狀態：處理中 In Progress。
資料庫：#1 = In Progress，#2 = Submitted
```

**原因**　`static/js/staff.js` 的 `selectReport` 沒有判斷回應是不是「最後一次點擊」的，先送出但較晚回來的回應會覆蓋畫面，而儲存按鈕使用畫面上的報修編號。

**修正**　`static/js/staff.js`：

- 每次點選都有序號，只有最後一次點擊的回應能更新畫面，較晚回來的舊回應直接忽略。
- 新的報修載入完成前，詳情與「儲存狀態」先隱藏，不會儲存到前一筆。
- 儲存時記住當下的報修編號；儲存期間若改點別筆，畫面維持在新點的那筆，不會被切回去。
- commit／PR：（填連結，例如 `CF-xx Fix staff page showing a stale report`）
