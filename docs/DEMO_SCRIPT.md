作業單第 11 節：前 4 分鐘展示功能，後 3 分鐘追一張 Story 到 Jira、程式和測試，再回答問題。

## 事前準備

- 刪掉 `instance` 資料夾，執行 `python app.py --seed-demo`，畫面上有 3 筆範例報修。
- 一般視窗開學生頁 http://127.0.0.1:5000/ ，另一個分頁先開 Jira 的 Story 卡片和 GitHub。
- 終端機保持在畫面上，等一下要示範重啟。

## 第一部分：功能展示（4 分鐘）

| 時間 | 操作 | 要講的重點 |
| --- | --- | --- |
| 0:00–0:40 | 空白表單直接按「送出報修」，再填完整送出 | 四個欄位各自提示；送出後拿到報修編號和「已提交」 |
| 0:40–1:10 | 在列表找到剛送出的報修，按「查看詳情」 | 列表和詳情一致，顯示目前狀態 |
| 1:10–2:00 | 搜尋 `wi-fi`，再搜 `WI-FI`；加上地點「圖書館」；最後搜 `zzzz` | 不分大小寫；關鍵字加地點是 AND；查無結果有提示 |
| 2:00–3:10 | 點「Staff 管理」用 staff 登入，把報修改成處理中；選已解決但備註留空被擋；填備註後結案；回學生頁看結果 | 結案一定要備註；學生看得到最新狀態和備註 |
| 3:10–3:40 | 終端機按 Ctrl+C 停掉，再執行 `python app.py`，重新整理 | 重啟後資料都還在 |
| 3:40–4:00 | 無痕視窗用 student 登入，開 /staff | 學生進不了管理頁，伺服器也會擋更新（403） |

## 第二部分：追一張 Story（3 分鐘）

建議用 S6「填寫備註後結案」。

1. **Jira**：打開 S6 卡片，念 User Story 和驗收條件，指出點數、Priority 理由和底下的 Subtask。
2. **程式**：在 GitHub 打開 `app.py` 的 `update_status`，指出「狀態是 Resolved 時，備註去掉空白後不能是空的」那幾行。
3. **測試**：打開 `tests/test_api.py` 的 `test_tc09_staff_updates_status_and_must_give_a_note_to_resolve`，說明它測了缺備註、空字串、只有空白三種情況；再指出測試紀錄 TC09 的實際結果和測試者。
4. **連結**：指出 commit 訊息裡的 Jira 卡號，以及 Story 卡片上貼的 PR 連結。

## 可能被問到的問題

- 為什麼只隱藏按鈕不夠？→ 伺服器端檢查角色，學生直接呼叫 API 也會被拒絕（401／403）。
- 資料存在哪裡？→ SQLite 檔案 `instance/campusfix.db`，所以重啟後還在。
- 關鍵字和地點同時用時怎麼運作？→ 兩個條件都要符合（AND），規則寫在頁面和 README。
- 你們遇到的缺陷？→ Staff 快速切換報修會存錯筆，說明重現、原因、修正和回歸測試。
- 每個人負責什麼？→ 依各自的 Jira 卡片和 commit 說明。
